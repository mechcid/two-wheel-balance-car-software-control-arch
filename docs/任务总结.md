## 2. I2C 配置修正

发现 `.ioc` 已设置 I2C2（PB10/PB11），但 C 文件仍是 I2C1（PB6/PB7）。用户明确确认 OLED、MPU6050 均接 PB10/PB11，因此对齐了：

- `Core/Src/i2c.c`、`Core/Inc/i2c.h`：I2C2 句柄、时钟、PB10/PB11 开漏复用，100 kHz。
- `Core/Src/main.c`：调用 `MX_I2C2_Init()`。
- `module/src/sensor_app.c`：两设备共用 `hi2c2`。
- `balance_car.ioc`：修正仍指向 I2C1 的初始化函数列表。

`.ioc` 里新增的编码器、PWM 等配置尚未完整生成到 Core；本次只实现请求中的屏幕/传感器，不把它们当成已完成的电机控制功能。

## 3. OLED 驱动具体做了什么

原驱动依赖 TI MSPM0 的 `ti_msp_dl_config.h`、`DL_I2C_*`，无法直接在 STM32 上使用。保留 8×16 字模与字符/数字显示接口，移植为 STM32 HAL 硬件 I²C。

- 按原驱动的 SSD1306 128×64 配置初始化；探测 7 位地址 0x3C/0x3D，HAL 调用时左移一位。
- `OLED_Init(&hi2c2)` 返回初始化状态；新增就绪、地址、错误、成功块数查询接口。
- 使用 1024 字节显存，修改字符只标记对应区域；`OLED_Poll()` 每次最多发送一个 16 字节数据块。
- 每次发送设置有限超时，失败后退出并标为未就绪；应用每 2 秒尝试重新初始化。MPU 失败时 OLED 仍可显示等待信息。
- OLED 内容每约 200 ms 更新。I²C 仍是阻塞事务，分块减少一次占用时间；采样为主循环调度，不能理解成硬实时精确 100 Hz。
- 保护无效行列、非字模字符、空指针、超长显示，并避免 INT32_MIN 取负溢出。坐标为行 1–4、列 1–16；字符串到行尾截断，不自动换行。

屏幕内容：标题 `MPU6050 / mg` 和 AX/AY/AZ。±2g 档下 `mg = raw × 1000 / 16384`，`1000 mg = 1 g`。**没有加入零偏校准**，之前约 1.2g 的静态偏置不会因为增加显示屏而消失。

## 4. UART 与 MPU 保持兼容

UART 搬迁后继续使用原有中断收发、命令解析与队列机制。`@status` 增加 OLED 状态；MPU 的 15 字节读取、前 14 字节解析的尾字节保护保留，原因见 `i2c_tail_diagnostic.md`。

本次直接复用了相邻 `blue_teeth/bt_assistant.py` 的 RFCOMM 后端，没有修改串口助手。临时验证文件放在 `/tmp`，没有重新向项目添加 tools/tests。

## 5. 实测结果

| 检查 | 结果 |
|---|---|
| Debug 构建 | 成功；Flash 47232 B / 64 KiB，RAM 区链接占用 7440 B / 20 KiB |
| Release 构建 | 成功；Flash 38044 B / 64 KiB，RAM 区链接占用 7440 B / 20 KiB |
| ST-Link 下载与校验 | OpenOCD 返回 Verified OK，随后复位运行；板上保留 Debug 固件 |
| GDB 调试 | 实际命中 main 源码断点，读取变量，随后恢复运行 |
| OLED 实物 | 0x3C 应答；用户明确确认显示正常、倾斜时数值变化 |
| MPU 实物 | 0x68，WHO_AM_I=0x68；蓝牙读取状态时成功 6089 次，失败 0 次 |
| UART/HC-05 | `@ping` 返回 PONG；`@status` 正常；rx_drop、tx_drop、err、tx_err 全为 0 |
| OLED 运行计数 | 同次蓝牙状态：ready=1、err=0、成功发送 2794 块 |
| 临时 OLED 主机检查 | 检查 0x3D 探测、初始全屏 64 块、无变化不重复发送、非法参数、INT32_MIN、I²C 失败及恢复入口；ASan/UBSan 通过 |

主机检查不替代硬件验证。测试运行环境不支持 LeakSanitizer 的进程检查，禁用了其泄漏检测，保留地址/未定义行为检查；OLED 实现不使用动态内存。链接 RAM 占用不等于实际运行峰值栈占用。

串口证据摘录：

```text

STATUS ready=1 addr=0x68 who=0x68 ok=6089 fail=0
UART rx_drop=0 tx_drop=0 err=0 tx_err=0
MPU,61324,2142,-1784,19448,-3345,-223,171,-95
```

计数是当时快照，重启后会清零。有限时间运行正常不等于完成长期可靠性测试。

## 6. VSCode 配置与使用

新增 tasks.json、launch.json、extensions.json，更新 settings.json 中模块路径并保留轻量索引设置。完整解释见 [VSCode编译烧录调试.md](VSCode编译烧录调试.md)。

- 只编译：终端 → 运行任务 → STM32: 编译 Debug。

已实测底层编译、烧录和 GDB 断点链路；没有在 VSCode 窗口亲自点击上述快捷键，不把静态配置核对称为 GUI 实测。
