# 电机模块架构改动说明

日期：2026-09-21。

> 本文记录独立模块版本。2026-09-22 已加入项目构建与调度，编码器采用用户精简后的单参数初始化；当前状态见 [电机控制接入说明](电机控制接入说明.md)。

这次只整理新加入的文件，**没有接入主循环，没有加入 CMake，没有烧录，也没有驱动电机**。所有新增注释使用中文。这是供阅读、讨论的代码版本，尚未完成具体电机驱动板的适配和实物测试。

## 1. 先记住三个动作

```cpp
motor.updateFeedback(dt_s); // 看电机现在转多快：更新编码器，再算 RPM。
motor.setDuty(0.3f);        // 直接给 30% 正向占空比，不保证实际转速。
speed.update(dt_s);        // 按目标转速自动算占空比，并写给 motor。
```

第三个动作内部已经包含第一个动作。使用速度控制器时，不要再额外更新一次编码器，否则会把同一段时间拆成两次采样。

三个主要对象的关系是：

```text
Encoder encoder         保存这一个编码器的计数
       ↑
Motor motor             保存引脚配置、编码器地址、每转计数；负责测速与输出
       ↑
MotorSpeedController    保存目标 RPM 和自己的 PID；负责追踪目标速度
```

需要直接输出占空比时，只使用 Motor；需要恒速时，再增加 MotorSpeedController。PID 是控制器用的计算工具，Motor 本身不需要知道 PID。

## 3. Encoder：每个编码器有自己的“小账本”

结构体核心就是你提出的三个成员：

```c
TIM_TypeDef *timer;
uint16_t last_cnt;
uint16_t now_cnt;
int16_t delta_cnt;
bool valid;
```

- `timer`：绑定硬件定时器地址，例如以后可以绑定 TIM1 或 TIM4。
- `last_cnt`：本次差分所用的上次计数。
- `now_cnt`：本次读取的计数。
- `delta_cnt`：两次读数间的正负增量。
- `valid`：基准和最近一次更新是否有效。

### 三个函数

```c
Encoder_Init(&encoder, timer); // 绑定地址，并以当前计数建立基准。
Encoder_Update(&encoder);     // 读取一次并算出增量。
Encoder_Rebase(&encoder);     // 放弃之前的位移，重新建立基准。
```

初始化不清零硬件计数器。比如硬件已经计到 123，初始化会让 last/now 都是 123、delta 为 0。

回绕也能处理：65530 → 4 记作 +10；4 → 65530 记作 -10。这里明确要求编码器计数范围为 0～65535，即 ARR=65535；每次采样间的真实计数位移绝对值必须小于 32768。恰好 32768 会返回失败，其他超过半范围的位移无法仅靠两个读数识别，需要从采样周期上保证。

失败后先重新建立基准再测量。外部不能同时更新同一个编码器；Motor 使用它时，更新权交给 Motor。

## 4. Motor：把计数变成速度，把占空比变成硬件输出

### 配置 MotorConfig

保存：

- 两个方向 GPIO。
- PWM 定时器和通道。
- Encoder 的地址。
- 输出轴每转计数 `counts_per_output_rev`。
- 正向、反向、零占空比时两个方向引脚的电平组合。
- 输出方向是否反转、编码器方向是否反转。
- 最大允许占空比 `duty_limit`。

电平组合必须依据实际驱动芯片手册填写。这次不默认把两脚低电平叫作“刹车”或“滑行”。两种反转标志独立，是为了让左右轮最终都满足“向前输出为正，向前测速也为正”。

`counts_per_output_rev` 替代含义模糊的 `ratio`，用正浮点数保存。若厂家提供的是电机轴单通道每转周期数，可以按“线数 × 解码倍频 × 减速比”计算；若已经是倍频后的输出轴计数，就直接使用，不能重复乘倍频或减速比。

### 常用接口

```cpp
Motor motor(config);       // 只保存配置，不读写硬件。
motor.begin();             // 检查配置、写零输出、建立测速基准。
motor.updateFeedback(dt_s);
float rpm = motor.state().rpm;
bool valid = motor.state().feedback_valid;
motor.setDuty(0.3f);
motor.stop();
```

`begin()` 不配置 GPIO，也不启动 PWM/编码器。以后接入时，必须先完成对应外设配置与启动。

`updateFeedback(dt_s)` 内部调用 Encoder_Update，再计算：

```text
RPM = delta_cnt × 60 / 每转计数 / dt_s
```

`dt_s` 单位是秒，应覆盖上次成功采样或建立基准到现在的实际时间。无效 dt 不推进编码器；失败时旧 RPM 保留，但 feedback_valid 变为 false，不能把它当作新测量。恢复时可调用 `rebaseFeedback()` 并重新开始计时。

例如假设每转 1000 计数、10 ms 内增加 10 个计数，则结果为 60 RPM。这里的 1000 只是例子，不是当前电机参数。

## 5. PID：独立计算，不碰电机

新接口按一次计算直接传入目标、测量和时间：

```cpp
PID::Config config;
config.kp = 0.01f;  // 仅演示写法，不能当作当前电机的整定参数。
config.ki = 0.0f;
config.kd = 0.0f;
PID pid(config);
float duty;
bool ok = pid.update(target_rpm, measured_rpm, dt_s, duty);
```

主要改动：

1. 积分项显式使用 dt，微分项显式除以 dt。原来的 ki/kd 隐含调用周期，不能直接照搬。
2. 微分作用于测量值，避免目标突变直接引起微分冲击；首帧微分为零。
3. 输出限幅和积分项限幅均显式配置，默认各为 -1～1。
4. 输出饱和且积分继续向饱和方向推动时，暂停该次积分；反向积分仍允许退出饱和。
5. `reset()` 清理历史，`configure()` 改参并清理历史；无效配置被拒绝，保留原配置。
6. 非有限输入或非正 dt 返回 false，将本次结果置零，不推进内部状态。

位置式和增量式都已保留，默认使用位置式。通过配置选择：

```cpp
config.mode = PID::Mode::Position;    // 位置式，默认。
config.mode = PID::Mode::Incremental; // 增量式。
pid.configure(config);              // 设置模式和参数，同时清空历史。
```

这两行模式赋值是两种备选写法，实际选择其中一种即可。MotorSpeedController 也使用同一份 PID::Config，无需增加另一套控制器。

两种模式都通过 `update(target, measurement, dt_s, output)` 返回最终限幅后的输出，**外部不要对增量式结果再累加**。

内部表达如下：

```text
位置式：本次输出 = 限幅(P本次 + I本次 + D本次)
增量式：本次输出 = 限幅(上次已限幅输出 + ΔP + ΔI + ΔD)
```

两种模式共享积分贡献限幅和条件积分抗饱和；ΔI 使用本次实际接受的积分变化。D 作用于测量值，使用本次实际 dt 计算斜率；增量式的 ΔD 是当前与上一帧 D 项之差，所以不依赖固定周期的二阶差分简式。

初始状态一致且未发生输出饱和时，两种表达应在浮点误差范围内一致。发生输出饱和后，增量式以上次已限幅输出作为累计基准，两种模式不保证相同轨迹。切换模式会清空历史，不承诺无扰切换；将来运行中切换时应先退出控制，重新配置后再使能。

`kd=0` 就是 PI，不需要再写一个 PI 类。微分没有额外低通滤波，电机测速建议从 PI 开始讨论。

## 6. MotorSpeedController：想恒速时才用它

```cpp
MotorSpeedController speed(motor); // 引用已有 Motor，不复制电机对象。
speed.configure(pid_config);
speed.setTargetRPM(60.0f);         // 设置目标，立即保存，不暗中滤波。
speed.enable();                   // 零输出、重新建立计数基准、清理 PID。
```

从 enable 成功的时刻开始计时，以后每个控制周期调用：

```cpp
speed.update(dt_s);
```

内部执行：

```text
motor.updateFeedback(dt)
    ↓
pid.update(目标 RPM, 测量 RPM, dt)
    ↓
motor.setDuty(计算结果)
```

`disable()` 清理 PID 并请求零输出。反馈、PID 或输出失败时，会退出使能状态并尝试停止，要求调用者检查后重新 enable，不会自己偷偷恢复。若硬件资源失效导致写入失败，软件无法保证物理电机已经停止，返回值必须检查。

PID 输出范围不能超出 Motor 的 duty_limit，避免 PID 不知道 Motor 又截掉一部分输出。控制器与 Motor、Encoder 必须一直存活；同一电机不能同时由速度控制器和其他代码写占空比。

目标为零表示“闭环尽力维持零速”，与 disable 的“退出控制并写零输出”不同。

## 7. pin_type 的扩展

保留了原来的类型名，替换为当前 STM32 使用的资源类型：

- `GPIO_pin_t`：端口与单引脚位掩码，提供写高/低函数。
- `GPIO_signal_t`：新增有效电平，用于使能/待机信号；通过 `GPIO_SetActive()` 表达启用/关闭。
- `PWM_pin_t`：定时器地址与通道编号；`PWM_SetDuty()` 写占空比，不修改频率。
- `UART_pin_t`：保存 HAL 串口句柄，不增加新的串口收发实现。

**PWM 通道填写整数 1～4，不使用 HAL 的 TIM_CHANNEL_x 值。** 两者编码不同，混用可能操作错误通道。

当前 PWM 实现约定：16 位计数器、向上计数、边沿对齐、PWM 模式 1、高电平有效。ARR 限定为 1～65534，使 CCR=ARR+1 能完整表示 100%；独立编码器定时器仍要求 ARR=65535。通道是否开启、模式是否符合约定，需要外设配置保证，函数不会替你配置。

同一定时器的不同通道共享频率；例如两个轮子的 PWM 若都用 TIM3，可以独立改占空比，但不能当作两个独立频率源。
