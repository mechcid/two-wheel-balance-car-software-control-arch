## 1. 从哪里看代码

```text
main.c：每 10 ms 调用 MotorApp_Update(当前毫秒)
    ↓
motor_app.cpp：管理左右电机、模式、目标和超时
    ├─ 开环：Motor.updateFeedback → Motor.setDuty
    └─ 闭环：MotorSpeedController.update
                  └─ 更新反馈 → PID → Motor.setDuty
```

| 文件 | 本次职责 |
|---|---|
| [motor_board_config.h](../Core/Inc/motor_board_config.h) | 接线、左右对应、1456 每转计数、输出限幅、PID 参数的集中配置 |
| [motor_board.c](../Core/Src/motor_board.c) | 板级 GPIO、定时器及 TB6612 STBY 控制；配置不全时不操作硬件 |
| [motor_app.h](../module/overlay_app/inc/motor_app.h) | 对 C 代码提供电机接口及只读状态 |
| [motor_app.cpp](../module/overlay_app/src/motor_app.cpp) | 保存两台 Motor 和速度控制器，计算实际 dt，管理工作模式 |
| [telemetry_app.c](../module/overlay_app/src/telemetry_app.c) | 解析应用命令，调用 MotorApp，不直接操作引脚 |
| [main.c](../Core/Src/main.c) | 初始化 MotorApp，并将其加入任务表 |
| [CMakeLists.txt](../CMakeLists.txt) | 加入板级文件、encoders.c、motor_app.cpp，启用 C++17 |

主文件仍是 C；`extern "C"` 接口使它能够调用 C++ 实现。C++ 对象使用静态存储区，不从堆分配内存。

## 2. 你的编码器改动保留了什么

保留单参数 `Encoder_Init(Encoder *)`：先给结构体的 timer 赋值，再初始化。Motor 中也继续使用此接口，没有恢复旧的双参数初始化或 Encoder_Rebase。

只补了一处判断：`Encoder_Update()` 在 valid=false 时拒绝继续计算，要求用 Encoder_Init 重新建立基准。否则半范围异常后旧基准会被继续使用，失效标记失去作用。同时修正 valid 注释：程序只能检测恰好 32768 的模差值，不能识别所有超过半范围的实际位移。

## 3. 板级配置

打开 `Core/Inc/motor_board_config.h`：

- 四个方向脚和 STBY 已按用户接线填写，见第 7 节。
- 左、右 PWM 通道各选 3 或 4。
- 左、右编码器定时器各选 TIM1 或 TIM4。
- 核对方向极性；两台轮子的前进方向最终应都对应正反馈。
- 当前 `MOTOR_BOARD_READY=1`；设为 0 时进入 UNCONFIGURED，不启用电机。

`.ioc` 已经提供的资源：

| 资源 | 引脚 |
|---|---|
| TIM3 CH3 / CH4 PWM | PB0 / PB1 |
| TIM1 编码器 | PA8 / PA9 |
| TIM4 编码器 | PB6 / PB7 |
| 方向与待机输出 | PA11、PA12、PA15、PB3、PB4 |

程序会检查五个输出引脚互不重复、PWM 通道和编码器定时器不重复。当前映射检查限定在上表的资源内；以后换板需要同时修改检查规则。

TB6612 配置采用：正向 IN1=1、IN2=0，反向相反。每个 Motor 的零输出使用短路制动组合；应用层停机、故障和初始化还会将共用 STBY 拉低，让两路输出高阻。方向名称仅为软件约定，实物前进方向仍需核对。[东芝 TB6612FNG 数据手册](https://toshiba.semicon-storage.com/info/datasheet_en_20141001.pdf?did=10660)

板级准备好后，TIM1/TIM4 配置四倍频、ARR=65535；TIM3 配置 20 kHz PWM、初始比较值为零。CCR 预装载关闭，方向变更前写零可立即作用于比较值；方向切换仍需实物检查，代码不是完整的电流保护控制。

这些定时器初始化集中在手写的 motor_board.c，使用 CMSIS 寄存器，因为工程目前未包含 HAL TIM 驱动文件。此次没有伪装成 CubeMX 已重新生成：以后若生成 tim.c，需要协调初始化所有权，避免两套代码重复配置定时器。

## 4. 串口怎么操作

命令沿用 `@命令:参数`，以 CRLF 结束。当前允许开环启动，速度闭环仍被锁定。

| 命令 | 作用 |
|---|---|
| `@mstatus` | 查看模式、RPM、占空比和反馈有效性 |
| `@ml:数值` | 暂存左轮目标，不立即执行 |
| `@mr:数值` | 暂存右轮目标，不立即执行 |
| `@mdrive` | 将暂存值解释为有符号占空比并提交 |
| `@mrun` | 将暂存值解释为 RPM 并提交给速度控制器 |
| `@mkeep` | 续期当前控制命令 |
| `@mstop` | 关闭 STBY、停止控制、清零目标并重新建立反馈基准 |

接线确认后的开环示例：

```text
@ml:0.10
@mr:0.10
@mdrive
```

这表示请求两轮 10% 占空比。当前允许范围为 ±40%，超出就拒绝，而不是静默裁剪。持续运行需要小于 1 秒间隔发送 `@mkeep`；建议每 200～500 ms 发送一次。不要反复提交目标来代替续期。

闭环示例将目标改为 RPM 后执行 `@mrun`。但闭环默认额外锁定：`MOTOR_SPEED_CONTROL_ALLOWED=false`，且两轮 PID 参数均为零。需要先验证编码器方向与计数，再整定参数并解锁。最大目标 120 RPM 只是初始软件限制，不代表已知电机额定转速。

位置式与增量式通过 `MOTOR_INCREMENTAL_PID` 选择。相同模式下更新 RPM 不重置 PID；模式切换会先停机并重置。一个目标值字段用于两种命令，切换开环/闭环前应重新设置左右值，避免混淆单位。

`mstatus` 的 RPM 以千分之一 RPM 的整数打印，占空比以千分数打印。模式为 STOPPED、DUTY、SPEED、FAULT、UNCONFIGURED。

## 5. 周期与故障策略

- MotorApp 在 main 任务表中每 10 ms 调度一次，排在传感器和显示之前。
- dt 根据本次和上次真实调用时间计算，不固定写成 0.01 秒。
- 无启动指令时保持 STOPPED，但可以持续读取手动转轮的编码器速度。
- 运行时超过 1 秒未收到控制续期，进入 FAULT 并关闭 STBY。
- 运行时两次控制调用间隔超过 50 ms，进入 FAULT。
- 编码器、控制器或输出失败，两路一起停机，不让另一侧继续运行。
- FAULT 不自动恢复；用 `@mstop` 检查并重新建立基准，然后显式提交新的启动请求。
- 运行时不执行 MPU/OLED 的重新初始化，避免原来的阻塞重连影响电机控制。

以上超时保护由主循环检查，**不是独立硬件看门狗**：CPU 若完全卡住或暂停调试，软件无法按时关闭输出。正常采集/显示事务仍是带超时的阻塞调用，本次没有实现硬实时平衡控制，也没有加入姿态闭环。

## 6. 验证结果

- 最终 Debug、Release 完整固件构建通过。Debug Flash 59080 B、RAM 8160 B；Release Flash 45612 B、RAM 8120 B。
- 最终 Debug 固件通过 ST-Link 完整下载、校验和复位。之前 SWD 失败在用户重新插拔 ST-Link 后恢复；此次下载使用 100 kHz。
- 此前主机模拟覆盖：未配置拒绝启动、默认停止、1456 计数测速、双轮开环输出、两种 PID 接入、目标更新、指令超时、控制间隔超时、续期、编码器故障/恢复和毫秒回绕。模拟通过不等于这些故障条件全部经过实机注入。
- 本次实测采用单路、40% 占空比、约 0.5 秒短脉冲，每次发停止指令并确认 STOPPED、两路 duty=0。保留 1 秒指令超时，测试不续期。
- 原候选 A=PWM1、B=PWM2 时，两路均无编码器反馈；用户确认电机未转、VM 已供电。交换 PWM 后分别获得反馈，因此确定实际通道绑定。
- 临时脚本和原始串口记录在 `/tmp/motor_integration_check`，可能被系统清理；关键结果汇总如下。未新增项目 tests/tools 目录。

## 7. 实测接线与结果（2026-09-22）

| 软件通道 | 驱动方向脚 | PWM（实测） | 编码器（实测） |
|---|---|---|---|
| L / A | IN1=PB3，IN2=PB4 | PB1 / PWM2 / TIM3_CH4 | PA8、PA9 / 编码器1 / TIM1 |
| R / B | IN1=PA12，IN2=PA11 | PB0 / PWM1 / TIM3_CH3 | PB6、PB7 / 编码器2 / TIM4 |

共用 STBY=PA15；PWM 20 kHz；编码器 1456 计数/输出轴圈。

首次正确绑定后，A 路 +40% 时原始反馈约 -74.175 RPM，B 路约 +65.934 RPM。配置中 A 路设置 `MOTOR_LEFT_ENCODER_REVERSED=true`，使正输出对应正反馈；B 路保持不反向。上述数值为加速过程中的一次采样，不能据此判断稳态转速或电机性能差异。

软件 L/R 目前只是通道命名。编码器符号统一也不代表两轮已经对应车体前进方向；整车控制接入前需按实际安装确认输出方向，若修改 OUTPUT_REVERSED，也要重新验证反馈符号。没有进行 PID 整定、负载测试或整车平衡测试。
