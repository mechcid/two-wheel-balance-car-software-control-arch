# 电机开环输出与测速

> 周期输出更新：三类独立打印函数现于 main 的 report_task 中组合，每 500 ms 输出；@stream 仅作为总开关，非零值不再选择数据种类。最新帧格式见 [README](../README.md#周期串口输出)。

2026-10-12。当前阶段只设置占空比并观察实测转速，不维持指定 RPM，也不接入姿态平衡控制。

## 阅读顺序

| 文件 | 职责 |
|---|---|
| `Core/Inc/motor_board_config.h` | 接线、1456 计数/圈、方向反转、40% 输出上限 |
| `Core/Src/tim.c`、`gpio.c`、`stm32f1xx_hal_msp.c` | CubeMX 对应的定时器、引脚和 SWD/JTAG 配置 |
| `Core/Src/motor_board.c` | 检查配置，以零输出启动 PWM/编码器，绑定资源和 STBY；不重写定时器参数 |
| `module/base/src/encoders.c` | 读硬件计数、计算有符号增量 |
| `module/base/inc/motor_types.h` | C/C++ 共用的单轮 MotorConfig、MotorState |
| `module/base/inc/motor.hpp` | 单轮方向、占空比、计数到 RPM 的换算 |
| `module/overlay_app/src/motor_app.cpp` | 双轮开环目标、实际 dt、启停、超时和故障 |
| `module/deferred/speed_control/` | 暂存 PID 和速度控制器，不参与当前构建 |

运行链路：main 每约 10 ms → MotorApp_Update → Motor.updateFeedback → Encoder_Update，然后在 DUTY 状态调用 Motor.setDuty。RPM = delta / 1456 / dt秒 × 60。Motor 独占对应编码器的更新，其他模块读取 MotorAppStatus。

## 初始化与配置

初始化顺序：HAL_Init（释放 JTAG、保留 SWD）→ MX_GPIO_Init（STBY 默认低）→ MX_TIM1/3/4_Init → MotorBoard_Init → MotorApp_Init。PWM/计数由 HAL Start 接口启动，STBY 保持关闭，等待占空比命令。

- TIM3：72 MHz，PSC=0（1-1）、ARR=3599，PWM1，高电平有效，CH3/CH4，20 kHz。
- TIM1/TIM4：PSC=0、ARR=65535、TI12 编码器模式，IC1/IC2 滤波均为 6，输入上拉。
- PA15 为 STBY；PB3/PB4、PA12/PA11 为方向脚。HAL_MspInit 保留 NOJTAG 配置。
- HAL_TIM_PWM_ConfigChannel 默认启用 CCR 预装载，因此在 `TIM3_Init 2` 用户区关闭两通道预装载，保持换向前写零立即生效的原有约定。此用户区必须在 CubeMX 再生成时保留。

已同步修改 `.ioc` 与生成式源码；本次没有运行 CubeMX GUI 再生成。下次生成后检查上述参数及用户区。PWM 频率只由 TIM3 配置决定，板级文件不再提供另一个 MOTOR_PWM_HZ。

L=A：PB1/TIM3_CH4，TIM1 编码器 PA8/PA9，编码器符号反转。R=B：PB0/TIM3_CH3，TIM4 编码器 PB6/PB7，编码器符号不反转。L/R 仍是软件名称，整车安装方向另行核对。

## 接口和操作

所有 MotorApp 时间参数及状态 timestamp_us 使用 Timebase_NowUs，任务调度仍保持约 10 ms。状态只有 UNCONFIGURED、STOPPED、DUTY、FAULT。目标占空比单独保存在内部 command.left_duty/right_duty；公开状态按 left/right 分组，其中 applied_duty 是实际写入占空比，rpm 是实测 RPM，feedback_valid 表示测速结果是否有效。配置也使用 config.left/right，取消左右轮下标约定。

命令以 CRLF 结束：

| 命令 | 作用 |
|---|---|
| `@ml:0.10`、`@mr:0` | 暂存两轮占空比，不立即输出 |
| `@mdrive` | 提交开环目标，下一次更新执行输出 |
| `@mstatus` | 查询模式、微秒时间、故障数、实测转速、占空比、有效性 |
| `@mkeep` | 续期当前命令 |
| `@mstop` | 关闭 STBY，停止两轮，清目标并重新建立计数基准 |

@ml/@mr 的单位现在统一为占空比，允许范围 ±0.40。@mrun 已移除。mstatus 的 rpm 仍以千分之一 RPM 的整数输出，占空比以千分数输出；时间字段改为 us。

停止时仍更新反馈，可手动转轮观察 RPM。持续运行需要小于 1 秒间隔续期；超过 1 秒未续期，或活动状态更新间隔超过 50 ms，进入 FAULT。任一轮失败，两轮一起停机。FAULT 后先 @mstop 恢复基准，再显式提交目标。保护由主循环执行，CPU 卡住或调试暂停时无法实时执行停机。

`bash tests/motor_open_loop/run.sh` 覆盖开环正反转、PWM 比较值、1456 计数测速、不同 dt、编码器双向回绕、微秒回绕、续期、指令超时、控制超时和单轮故障引发双轮停机及恢复。IMU 原有测试继续运行。尚未烧录或测量实际 PWM/转速；旧文档里的实测记录属于此前版本。

## 配置与状态复用（2026-10-13）

MotorAppConfig 仅组合 MotorConfig left/right 与共用 STBY 回调。MotorAppStatus 组合 MotorState left/right 和应用级模式、时间戳、故障数；旧 MotorWheelConfig、MotorWheelStatus 及配置转换已删除。状态占空比字段统一为 applied_duty，串口格式保持不变。

左右 Encoder 在 motor_board.c 静态定义，MotorConfig.encoder 指向对应对象，MotorApp 不再创建编码器。对象及其定时器必须独立且存活到应用结束；MotorApp_Init 拒绝两轮共享同一编码器对象或计数器。运行期间由对应 Motor 独占更新。

公共 C 结构体没有 C++ 成员默认值：配置应先零初始化，再显式填写引脚、计数比例、真值表和 duty_limit。每轮限幅独立；当前板级两轮仍为 0.40。Motor 内部状态继续以零初始化开始。

## 编码器位移（2026-10-13）

MotorConfig.radius_m 为轮半径，当前板级 MOTOR_WHEEL_RADIUS_M=0.0325f（32.5 mm）。必须配置为有限正数。MotorState 新增 total_counts（int64_t 有符号累计计数）、signed_travel_m（有符号累计轮行程，米）与 travel_valid（累计连续性）。

有符号累计轮行程 = total_counts / counts_per_output_rev × 2π × radius_m。直接累计编码器增量，不积分 RPM；正反向由 encoder_reversed 统一，与 RPM 符号相同。前进后退相互抵消，表示有符号轮行程，不是累计绝对路程，也不是车体二维位置。轮滑会影响由轮行程推断的地面位移。

成功 begin 建立新原点并清零。正常 stop、rebaseFeedback、应用停止和重新启动均保留累计值；重建测速基准前先补计尚未读取的增量。停止状态下手动转轮仍累计。

若计数器配置或基准失效、出现恰好 32768 的歧义增量，则保留已知行程，travel_valid=false；恢复后继续累计可观测计数，但不会自动将完整性标志恢复为 true。仍须满足原编码器约束：相邻观测真实增量绝对值小于 32768。长时间停采后无法仅凭寄存器发现全部丢圈，不能保证恢复缺失行程。

@mstatus 新增 WHEEL travelL/travelR 行，单位 mm，并报告两轮位移连续性；原转速/占空比行保持。内部米值由整数总计数重新换算，避免每帧浮点累加误差；float 的米值在大行程下仍有分辨率限制，精确计数保留在 total_counts。


## 双轮位移增量采样（2026-10-14）

MotorState.delta_travel_m 为本次编码器采样的有符号轮行程，单位 m，直接由计数增量换算；delta_valid 表示单段是否可信。失败清零增量并标记无效；静止时零增量仍有效。该标记独立于 travel_valid：累计曾丢失计数，恢复基准后后续单段仍可有效。电机接线、半径、计数比例与正负方向配置未修改。

MotorAppStatus.sequence 在每次双轮采样发布时递增，包括无效帧；初始化为 0 且不发布，uint32_t 自然回绕。timestamp_us 为采样区间末端，interval_us 为距上次采集的间隔，两轮在主循环内依次读取、共用逻辑采样区间，并非硬件同时锁存。valid 仅在两轮单段均有效且 0 < interval_us <= 50000 时为真；超长间隔不作为可信二维积分输入。此时间限制不能检测所有编码器丢圈，仍须满足真实计数增量绝对值小于 32768 的约束。

通过 MotorApp_SetFeedbackCallback 注册一个同步、非重入的短回调，后续里程计可在这里处理每一段（包括停止/超时的补采样）。注册不重放历史；建议初始化前注册。回调内不得调用 MotorApp 控制或采样接口，不应阻塞或打印。读取不会清除有效标记，其他消费者可独立观察；GetStatus 仅保存最新状态，低频轮询不能代替逐帧消费。

消费者各自保存上一序号；相同序号跳过，差值按 uint32_t 计算，差值不为 1 表示漏帧。无效帧也要推进已处理序号，同时标记自身里程计连续性丢失。启动时尚无采样，不能消费初始化状态；中途接入无法恢复之前路径。时间戳用于姿态对齐，不能将旧增量搭配当前航向分解。

正常停止补采样会发布新帧；采集成功已推进编码器基准，不再额外读取 CNT，以免丢掉两次读取之间的计数。启动提交占空比不额外采样。反馈失败时两轮仍各尝试一次采样，随后只关闭输出，不再次采样覆盖失败帧。FAULT 状态暂停采集，恢复时补采样也必须经过有效性检查。同一时间戳执行停止仍发布帧，但因区间为零标记无效。

@mstatus 新增 STEP 行：seq、dt_us、双轮 valid、左右增量 L/R（微米）及各轮 wheel_valid。周期 MOTOR 输出格式保持原样；STEP 是查询瞬间的最新段，不能从低频串口查询重建全部轨迹。本次只提供增量及消费接口，尚未实现 X/Y 里程计。
