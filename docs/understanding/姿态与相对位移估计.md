# 姿态与相对位移估计

> 目录更新（2026-10-12）：现已分为 `module/base/{inc,src}` 和 `module/overlay_app/{inc,src}`。本文中的平铺/撤回描述为历史记录，具体文件引用已更新；当前目录以 [README](../README.md#目录) 为准。

> **历史实现记录：2026-10-12 起，项目已取消 MPU6050 的速度和位移积分，只保留姿态估计。** 下文保留前次实现供对照，其中位置状态、`@pzero`、`@still`、旧 OLED 页面及含位移的 POSE 帧均已删除。当前代码及接口请阅读 [MPU6050 仅姿态估计调整说明](MPU6050仅姿态估计调整说明.md)。

## 1. 本次增加了什么

在原有 `mpu6050 → sensor_app → 显示/串口` 的结构上，新增 `motion_app → motion_estimator`。原始计数和校准后的六轴数据仍由 `sensor_app` 管理，姿态和位移有自己的状态，不混进传感器驱动。OLED 当前同屏显示姿态与累计位移，也可通过访问接口、串口和调试器读取。目录分层已暂时撤回，源文件统一放在 `module/src`，头文件统一放在 `module/inc`，方便用户先查看功能差异。

| 文件 | 职责 |
|---|---|
| `module/base/src/TIM_IT.c`、对应头文件 | 计算 TIM2 周期，启动中断，记录节拍，提供高分辨率计时 |
| `module/overlay_app/src/motion_app.c`、对应头文件 | 主循环消费节拍、采集、计算实际 dt，持有一个算法实例及统计信息 |
| `module/overlay_app/src/motion_estimator.c`、对应头文件 | 不依赖 HAL 的姿态、重力扣除、速度及相对位移算法 |
| `module/overlay_app/src/sensor_app.c` | 校准数据发布、检查新样本、保存输出速率设置用于重连 |
| `module/base/src/mpu6050.c` | 增加输出速率设置和 DATA_RDY 查询，保留原有量程及尾字节保护 |
| `Core/Src/main.c` | 初始化 `motion_app`，主循环优先轮询；移除原来的 10 ms 采集任务 |
| `module/overlay_app/src/telemetry_app.c` | 增加姿态查询、位置归零、明确静止及姿态上报命令 |

```text
TIM2 IRQ → HAL_TIM_PeriodElapsedCallback → 记录节拍
主循环   → MotionApp_Poll → SensorApp_Update → 修正后的六轴数据
                         → MotionEstimator_Update → 姿态、运动加速度、速度、位置
         → 原有 scheduler → 电机、显示、串口、故障恢复
```

中断只做整数节拍计数。阻塞式 HAL I2C 读取依赖超时和总线状态，不适合放在高优先级定时中断里。因此，当前硬件节拍是精确的，**主循环读取和解算会有延迟，不是保证每 2 ms 完成一次采集的硬实时实现**。后续若需要严格采样时序，应引入 MPU 的 DATA_RDY 引脚/FIFO 和 DMA，再讨论调度和共享数据同步。

## 2. 坐标和负号：先明确输入含义

目前 main 保留用户的校准参数，包括 `accel_scale={-1,-1,-1}`，陀螺仪比例仍是 `{1,1,1}`。显示和 `SensorApp_GetSample()` 依然能看到静止时 Z 约为 −1g。

算法采用下面的约定：

- 机体轴沿陀螺仪当前的右手轴定义；参考坐标系 Z 向上。
- `MotionConfig.accel_sign=-1`，在算法内部把三轴加速度输出整体取反，恢复成用于标准姿态解算的比力。水平静止时内部 Z 为 +1g。
- `q` 是机体到参考坐标系的旋转四元数，顺序为 w、x、y、z。
- 首次静止采集建立 roll/pitch；yaw 初始为零。参考系 X/Y 由此确定，位置原点在启动处，初速度假设为零。

**三轴同时反号不属于一个安装旋转。** 这里将它作为“加速度输出整体取反”的约定处理，没有跟着反转陀螺仪。如果以后车体轴与模块安装轴不同，应先用同一个正确的旋转映射加速度和角速度，再进入算法。当前参考系 X/Y 不等同于负号处理后的三根加速度通道标签；没有额外定义车头方向、安装旋转或地理方向。

算法内部先做：

$$
\mathbf f_b = -\mathbf a_{\mathrm{sample}}\,g
$$

再根据姿态旋转到参考系：

$$
\mathbf a_w = R(q)\mathbf f_b - \begin{bmatrix}0\\0\\g\end{bmatrix}
$$

因此，静止、倾斜时均应得到接近零的运动加速度。不能在机体坐标中始终只给 Z 通道加上/减去 1g。

## 3. 姿态估计的步骤

采用四元数形式的重力方向互补反馈，与 Mahony 非线性互补滤波的基本思路一致。本实现根据数学关系独立编写，没有复制第三方库代码，也没有增加积分式陀螺仪零偏估计。

1. 陀螺仪角速度从度/秒换算为弧度/秒，用实际 dt 推进四元数，再归一化。
2. 加速度经过一阶低通，作为重力方向的参考。
3. 将测得的重力方向与当前姿态预测的方向做叉积，得到倾角误差；按增益反馈到角速度。
4. 若当前加速度模长偏离 1g 超过阈值，或方向残差超过 30°，暂停本帧的加速度反馈。
5. 欧拉角只在读取/上报时计算，避免每个节拍都调用三角函数。

`accel_trusted` 只表示本帧通过了反馈门限，**不是姿态正确的证明**。持续的小加速度可能仍通过门限，并被误认为倾斜；低通也会引入延迟。仅凭六轴 MPU 无法在任意运动下完全区分倾斜和加速度，也无法纠正 yaw 的长期漂移。

默认参数在 `MotionEstimator_DefaultConfig()` 中集中设置：

| 参数 | 默认值 | 用途 |
|---|---:|---|
| `accel_sign` | −1 | 当前项目加速度的整体输出符号 |
| `gravity_mps2` | 9.80665 | 重力大小 |
| `correction_gain` | 2 /s | 重力方向纠正强度；设 0 可关闭反馈 |
| `accel_cutoff_hz` | 10 Hz | 重力参考低通截止频率 |
| `linear_cutoff_hz` | 20 Hz | 运动加速度低通截止频率 |
| `accel_tolerance_g` | 0.12g | 模长门限 |
| `max_dt_s` | 0.05 s | 超过此缺样间隔时停止积分 |

低通使用随 dt 变化的系数，不写死采样率：

$$
k=2\pi f_c\Delta t,\quad \beta=\frac{k}{1+k}
$$

$$
y_k=y_{k-1}+\beta(x_k-y_{k-1})
$$

主文件可修改 `motion_config` 后再传给 `MotionApp_Init()`。初始化接口会复制配置，局部配置变量不需要保持生命周期。

## 4. 速度与位移

扣除重力后的参考系加速度低通后，用梯形积分：

$$
\mathbf v_k=\mathbf v_{k-1}+\frac{\mathbf a_{k-1}+\mathbf a_k}{2}\Delta t
$$

$$
\mathbf p_k=\mathbf p_{k-1}+\frac{\mathbf v_{k-1}+\mathbf v_k}{2}\Delta t
$$

输出在 `MotionState` 中分开保存：

- `linear_mps2[3]`：运动加速度，m/s²。
- `velocity_mps[3]`：速度，m/s。
- `position_m[3]`：相对启动/归零原点的位移，m。
- `valid`：最近一次解算有效，不表示绝对位置可信。
- `discontinuity`：发生异常输入、总线失败或过长采样间隔，轨迹已不连续。

启动时应保持静止。发生异常/超过 `max_dt_s` 的间隔时，停止该次积分并使速度归零；下一份可信的加速度重新建立倾角、保留上一次航向和位置，不填补缺失期间的运动。直到手动归零，`discontinuity` 都会保留，避免把恢复后的轨迹误认为完整轨迹。

`MotionApp_ResetPosition()` 仅将速度、位置和不连续标志清零，不清空姿态和校准。运行中调用意味着主动假设此刻速度为零，并设新原点。

当前没有自动静止判断。匀速与静止时，IMU 可能读到同样的重力和零角速度；仅凭“小角速度、模长约 1g”不能证明静止。确实不动时可调用 `MotionApp_SetStationary(true)`，每次更新将速度归零、保持位置；移动前必须调用 `false`。

**当前位移是纯 IMU 积分实验结果，不是可靠的三维定位。** 即使只有 0.01g 的残余加速度误差，10 秒也会累积约 4.9 m 的位置误差；倾角误差会把重力投影进运动加速度。平衡车后续应结合编码器和轮径估计平面速度/路程，再融合姿态。此次未加入编码器融合，也未驱动电机。

## 5. TIM2 实际频率与 dt

代码读取 `TIM2->PSC`、`TIM2->ARR` 和 RCC 的 APB1 时钟配置，不使用 500 Hz 宏：

$$
f_{\mathrm{update}}=\frac{f_{\mathrm{TIM2}}}{(PSC+1)(ARR+1)}
$$

STM32F1 上，APB1 不分频时 TIM2 时钟等于 PCLK1；APB1 分频时 TIM2 时钟为 PCLK1 的两倍。当前：

```text
PCLK1 = 36 MHz，APB1 分频为 2 → TIM2 时钟 = 72 MHz
PSC = 72-1 = 71
ARR = 2000-1 = 1999
周期 = 72 × 2000 / 72000000 = 0.002 s
频率 = 500 Hz
```

`TIM_IT_GetTiming()` 每次调用都会重读配置；`motion_app` 在初始化时保存时序并设置 MPU 输出率。这里的“动态计算”是按实际配置计算，不是正在运行时无缝更改 PSC、ARR 的控制接口。修改 CubeMX 配置后重新生成、编译和复位即可采用新周期。运行中改寄存器时，需要同步重新配置传感器和时间基准，当前没有实现此流程。

**算法 dt 并不直接使用理论 2 ms。** `motion_app` 在主循环开始采集时读取 Cortex-M3 的 DWT 周期计数器，计算相邻成功读取的实际间隔；长间隔用毫秒时基兜底，避免 DWT 约 59.65 秒回绕造成假短间隔。时间戳仍是主机开始读取的时间，未连接 MPU DATA_RDY 引脚，不能等同于传感器内部采样时刻。

节拍积压时只读最新一帧；`missed_ticks` 累计跳过的调度节拍，不是 MPU 丢帧数量。没有 FIFO，不能恢复未读取的传感器历史帧。`no_data` 统计轮询时还没有新数据的次数，TIM2 与 MPU 两套时钟未同步，因此出现少量此计数并不必然是通信故障。主循环的 OLED 事务、故障恢复及调试暂停都会影响实际采集间隔。

## 6. MPU 和总线配置变更

- MPU 保留 ±2g、±250°/s 和 DLPF=3，换算系数不变。
- DLPF=3 时基础输出为 1 kHz。新增接口按请求频率选择最接近的合法整数分频，实际值通过接口返回。TIM2=500 Hz 时选择 `SMPLRT_DIV=1`。
- 启用数据就绪状态，在读取六轴前查询 `INT_STATUS`。无新样本返回 `HAL_BUSY`，不更新样本，不记通信失败，也不参与积分。
- 输出率要求保存在 `sensor_app`，故障重连后重新应用；驱动初始化默认仍为 100 Hz，应用初始化再设置当前 TIM2 对应速率。
- 当前 I2C2 保留用户设置的 100 kHz，代码与 `.ioc` 一致。用户反馈此前提出的 400000 在当前 CubeMX/硬件配置下标红报错，不能使用；此前的提速修改已撤回。MPU/OLED 仍共用 PB10/PB11。
- 100 kHz 下状态查询、15 字节读取及 OLED 传输的总耗时可能超过 2 ms。因此 TIM2 的 500 Hz 节拍不代表主循环每秒取得 500 份新样本；代码使用实际 dt、统计积压，实际吞吐待总线恢复后验证。
- 校准参数仍允许负比例，补充拒绝零比例及绝对值大于 10 的比例，避免校准把整轴数据清零。

## 7. 调用和串口查看

业务通过以下接口获取结果，默认仅供主循环使用，未实现并发快照：

```c
const MotionState *motion = MotionApp_GetState();
float degrees[3];
MotionApp_GetEuler(degrees);
/* degrees: roll、pitch、yaw；motion->position_m: X、Y、Z 相对位移 */
```

串口命令仍要求 `@` 开头、CRLF 结尾；蓝牙助手中可输入下列文本及转义结尾：

| 命令 | 行为 |
|---|---|
| `@pose\r\n` | 查看定时频率、实际 MPU 输出率、dt、积压统计、姿态、运动加速度、速度和位置 |
| `@pzero\r\n` | 速度和位置归零，清除轨迹不连续标志，保留姿态 |
| `@still:1\r\n` | 明确告知算法当前静止；移动前务必取消 |
| `@still:0\r\n` | 取消静止声明，恢复积分，默认此状态 |
| `@stream:2\r\n` | 每约 200 ms 输出一帧姿态及位移 |
| `@stream:1\r\n` | 恢复原来的六轴校准数据帧，默认此状态 |
| `@stream:0\r\n` | 停止连续上报，便于查询状态 |

姿态帧格式：

```text
POSE,时间_ms,valid,roll_mdeg,pitch_mdeg,yaw_mdeg,X_mm,Y_mm,Z_mm
```

查询中 `hz_m` 是频率乘 1000，`dt_us` 是微秒；角度使用毫度，运动加速度使用 mm/s²，速度使用 mm/s，位置使用 mm。没有启用浮点 printf；超出整数范围的运动遥测值饱和输出。

建议上电静止后先查看 `@pose`，应当 `valid=1`，频率约 `500000` mHz，静止运动加速度接近零。确认小车静止后可先设 `@still:1` 检查倾角变化；需要测试位移时先取消静止并归零，再观察短时间趋势。

## 8. 编译与验证边界

数学运算及三角函数库使原来的 Debug 无优化固件超过 64 KiB。顶层 CMake 将 Debug 的应用和 HAL 设为 `-Og`，保留 `-g3`；纯算法文件使用 `-O2`，加快无 FPU 的 Cortex-M3 运算。Release 保持原有 `-Os`，算法文件仍为 `-O2`。未扩大链接脚本中的 Flash 容量。

优化后仍可以断点调试，但部分局部变量可能被优化掉，单步顺序也可能与源代码不完全一致。

本次验证：

- Debug、Release 交叉编译通过；算法初次实现时 Flash 分别为 64,288 / 60,608 字节（64 KiB 上限），RAM 分别为 8,656 / 8,640 字节。当时 Debug 的 Flash 余量为 1,248 字节。后续页面改造的体积见 [本轮修改详解与代码阅读指南](本轮修改详解与代码阅读指南.md)。
- 主机模拟检查：水平静止、初始倾斜时三轴重力扣除、绕 Z 转动的相对航向、倾角反馈收敛、已知加速度的速度/位移积分、匀速保持、明确静止、缺样恢复及非法输入。
- 传感器适配模拟检查：无新数据不重复发布、负比例校准、零/越界比例拒绝、读取失败保留旧样本、重连恢复 500 Hz 输出率。
- 定时器模拟检查：PSC/ARR 加一、APB 倍频/不倍频、ARR=1999 与 ARR=2000 的区别、模式检查和节拍积压。
- 数学模拟使用地址/未定义行为检查；因运行环境不支持泄漏检查，关闭了泄漏检查，算法本身不动态分配内存。
- 临时验证文件放在 `/tmp`，未重建项目内的 tests/tools 目录。

**算法初次实现时只做软件验证；后续目录/OLED 页面整理后的固件已通过 DAP 下载、校验和复位。** HC-05 查询正常，但 MPU 与 OLED 均报告 I2C 超时，未取得有效运动数据，尚未完成新页面肉眼验收。当前总线配置为 100 kHz；实际采集吞吐及姿态/位移精度仍待板端验证。

## 9. OLED 页面及目录整理

此前按 base/overlay_app 进行分类，现已暂时恢复 src/inc 平铺。以下仅记录原分层设想：

- base：MPU6050、OLED/字模、UART、编码器、Motor 底层输出封装、引脚类型、TIM_IT。
- overlay_app：sensor_app、motion_app、motion_estimator、motor_app、转速控制器/PID、display_app、telemetry_app、scheduler。PID、调度器和姿态算法不属于硬件驱动，暂随上层代码放在此处。
- 板级具体引脚绑定仍在 Core；顶层 CMake 和 VSCode 的备用 includePath 已恢复平铺路径；算法优化配置也指向原目录，功能保留。

OLED 128×64、8×16 字模，每行 16 个字符，因此用两列同时显示：

```text
RPY deg   XYZ mm
R -12.3 X   +123
P +45.7 Y     -5
Y+180.0 Z     +0
```

R/P/Y 分别为 roll/pitch/yaw，右列 X/Y/Z 是参考系中的累计相对位移。角度保留 0.1°，位移显示到毫米；数值均四舍五入，未启用浮点 printf。

- `GAP`：标题改为 `RPYdeg XYZmm GAP`，表示轨迹曾因缺样等原因中断。`@pzero` 可设新位置原点并清除此标志。
- `POSE waiting...`：无有效/新鲜解算数据；数值改为 `--`，避免展示旧结果。
- `+OVF` / `-OVF`：位移超过 ±999999 mm 栏位范围，不截断成错误数值。完整物理量仍可通过状态接口读取。
- 显示函数仅格式化传入的姿态和位移，不采集、不积分；main 读取算法状态和欧拉角后传入，仍每 200 ms 刷新画面。

迁移及显示布局通过 Debug、Release 构建和模拟 OLED 行宽、正负号、舍入、超限、GAP、过期/无效数据检查。
