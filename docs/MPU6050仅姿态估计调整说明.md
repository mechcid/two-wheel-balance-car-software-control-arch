# MPU6050 仅姿态估计调整说明

记录日期：2026-10-12。

## 1. 本次决定

MPU6050 保留六轴和温度采集、校准，以及姿态估计。加速度到速度、位移的积分已从实现中删除，后续小车路程和位移由编码器方案完成。

原因是两次积分会积累加速度残差：若残留一个恒定误差 b，经过时间 t，位置误差为 b×t²/2。姿态误差还会将部分重力误认为运动加速度。低通滤波能减轻跳动，却不能消除这种累计误差。

文件仍放在 `module/src`、`module/inc`，继续沿用 `motion_estimator` 和 `motion_app` 的名字，便于在原路径审阅改动。本次没有重新分类或迁移目录。

## 2. 现在各层负责什么

```text
TIM2 中断 → TIM_IT 记录节拍
主循环    → MotionApp_Poll
             → SensorApp_Update → MPU6050 原始采集与校准
             → MotionEstimator_Update → 四元数姿态
          → scheduler → OLED、串口、电机等任务
```

| 模块 | 当前职责 |
|---|---|
| `mpu6050.c/.h` | 硬件 I2C 通信、寄存器设置、读六轴和温度 |
| `sensor_app.c/.h` | 保存原始样本，校准并发布修正后的样本 |
| `TIM_IT.c/.h` | 从定时器配置计算频率，记录中断节拍，提供计时 |
| `motion_app.c/.h` | 消费节拍，采集，计算真实 dt，保存姿态算法实例和统计 |
| `motion_estimator.c/.h` | 纯数学姿态算法，不依赖 HAL，不控制调度周期 |
| `display_app.c/.h` | 将传入的姿态角格式化并显示 |
| `telemetry_app.c` | 命令处理、状态查询、样本与姿态上报 |

本次修改集中在后三个应用/算法模块及其相关头文件；板级配置和主循环调用方式继续使用已有实现。

## 3. 删除了哪些内容

### 3.1 算法内部

从 `motion_estimator.c/.h` 删除：

- 加速度旋转到参考系后扣除重力的计算链路。
- 运动加速度低通滤波和历史值。
- 加速度到速度、速度到位移的梯形积分。
- `linear_mps2`、`velocity_mps`、`position_m` 状态。
- `previous_accel`、`known_stationary` 等积分辅助状态。
- `gravity_mps2`、`linear_cutoff_hz` 参数。
- `MotionEstimator_ResetPosition()`、`MotionEstimator_SetStationary()`。

重力方向计算仍然存在：姿态融合需要比较“测得的重力方向”和“当前姿态预测的方向”。这用于纠正倾角，不再用于生成运动加速度或位置。

### 3.2 应用和交互

从 `motion_app.c/.h` 删除位置归零、静止声明的转发接口，即 `MotionApp_ResetPosition()`、`MotionApp_SetStationary()`。

从 `telemetry_app.c` 删除 `@pzero`、`@still` 注册和处理函数，以及 `@pose` 的 MOVE 输出行。OLED 不再显示 X/Y/Z 位移。

这些接口已实际删除，不是留下空函数或持续输出零。如果外部代码仍调用它们，需要修改调用方。

## 4. 保留下来的姿态算法

### 4.1 输入与状态

`MotionEstimator_Update()` 输入：

| 参数 | 单位与含义 |
|---|---|
| accel[3] | 校准后的三轴加速度读数，g |
| gyro[3] | 校准后的三轴角速度，度/秒 |
| dt_s | 相邻成功采样的实际间隔，秒 |

算法没有内置 500 Hz 调度周期。`motion_app` 根据计时结果提供 dt，其他工程也可以在自己的任务或调度器中调用算法。

`MotionState` 现在只包含：

```c
typedef struct {
    float q[4];
    bool valid, accel_trusted;
    bool discontinuity;
} MotionState;
```

- `q`：w、x、y、z 顺序的四元数，表示机体系到参考系的旋转。
- `valid`：当前是否已有可用姿态，不代表姿态没有误差。
- `accel_trusted`：本帧是否接受加速度方向作为倾角反馈；不代表完全没有运动加速度。
- `discontinuity`：曾发生采样/通信中断，无法保证相对姿态连续。

### 4.2 更新步骤

1. 检查输入和 dt 是否有限、是否超出允许范围。
2. 按当前项目符号约定转换加速度，将角速度转换为弧度/秒。
3. 首次取得接近 1g 的样本时，用加速度方向建立 Roll、Pitch，Yaw 初始为零。启动时应保持静止。
4. 后续对加速度做一阶低通，提取较平稳的方向参考。
5. 同时检查原始模长是否接近 1g，以及滤波方向与预测方向是否相差小于 30°。通过时，将方向误差反馈到角速度；未通过时仅用陀螺仪推进。
6. 用角速度和实际 dt 更新四元数并归一化；按需转换成欧拉角供显示和控制读取。

这是基于重力方向反馈的互补姿态融合，未加入卡尔曼滤波、磁力计或位移计算。持续的小幅运动加速度仍可能影响倾角；门限只能减少明显干扰。

### 4.3 当前参数

| MotionConfig 字段 | 默认值 | 作用 |
|---|---|---|
| accel_sign | -1 | 将当前静止 Z≈-1g 的读数转为内部 Z≈+1g |
| correction_gain | 2，单位 1/s | 加速度方向反馈强度 |
| accel_cutoff_hz | 10 Hz | 加速度方向低通截止频率 |
| accel_tolerance_g | 0.12g | 加速度模长相对 1g 的允许偏差 |
| max_dt_s | 0.05 秒 | 超过此间隔则姿态失效，等待重建 |

main 中用户设置的校准值保留。三轴加速度整体反号在这里作为输出符号约定处理，不能代替模块安装方向到车体坐标的旋转映射；陀螺仪轴仍沿已有右手定义。

### 4.4 数据中断如何处理

通信失败、异常输入或间隔过长时，保留上次四元数，但置 `valid=false` 并设置 `discontinuity=true`。恢复后，用可信加速度重建倾角，保留上次 Yaw；缺样期间的转动无法补算。

GAP 提示会保留到算法重新初始化（例如重新上电），不是恢复一帧有效数据就自动消失。原来通过 `@pzero` 清除标记的方式已经删除，当前没有新增串口姿态复位命令。

MPU6050 没有绝对航向参考。Roll、Pitch 可利用重力方向纠正；Yaw 为相对启动方向的估计，仍可能随陀螺仪零偏漂移。

## 5. 如何访问姿态

现有访问方式保留：

```c
const MotionState *state = MotionApp_GetState();
float degrees[3];
MotionApp_GetEuler(degrees);  /* Roll、Pitch、Yaw，单位度。 */
```

使用前检查 `state->valid`，需要时还要根据 `MotionApp_GetStatus()->timestamp_ms` 检查数据新鲜度。显示层继续使用 main 传入的可用性判断，不自行采集或推进算法。

如果已有控制器读取四元数，仍能通过 state->q 访问。读取角度不要求每次复制全部算法状态。

## 6. OLED 与串口协议

### OLED

```text
ATTITUDE / deg
Roll   -12.3
Pitch  +45.7
Yaw   +180.0
```

每行完整覆盖 16 字符，角度保留一位小数；标题在发生中断后显示 `ATTITUDE GAP`。数据无效或不新鲜时显示 `POSE waiting...` 和三行 `--`。

### 串口

命令仍以 CRLF 结束：

| 命令 | 行为 |
|---|---|
| `@pose` | 查询定时器频率、MPU 输出率、实际 dt、统计、姿态和标志 |
| `@stream:2` | 周期输出姿态帧 |
| `@stream:1` | 周期输出原有校准六轴/温度 MPU_C 帧，默认模式 |
| `@stream:0` | 关闭周期上报 |

姿态帧已缩短为六列：

```text
POSE,时间_ms,valid,roll_mdeg,pitch_mdeg,yaw_mdeg
```

`mdeg` 为千分之一度，例如 -12340 表示 -12.340°。**旧解析程序如果期待末尾 X_mm、Y_mm、Z_mm 三列，需要同步修改。** 当前 `@pose` 的角度状态行是：

```text
POSE valid=1 trusted=1 gap=0 rpy_mdeg=-12340,45670,179990
```

`MPU_C` 帧、普通状态查询和电机命令继续沿用现有协议。

## 7. 定时器、I2C 和编码器

TIM2 频率仍根据实际时钟、PSC、ARR 动态计算。当前时钟 72 MHz、PSC=72-1、ARR=2000-1，对应 500 Hz；没有在算法里新增写死的频率宏。

I2C2 保持用户配置的 **100000 Hz**，本次没有修改 `.ioc`、外设初始化、CMake 或 VSCode 配置。定时器 500 Hz 和实际成功采集频率不同，后者仍取决于主循环、I2C 吞吐和样本是否就绪。

本次未实现编码器里程，也未把 IMU 结果加入电机闭环。后续可在独立模块中使用编码器计数变化和轮子周长计算轮子路程：

```text
轮子路程增量 = 编码器计数增量 / 每输出轴圈计数 × 轮子周长
```

当前每输出轴圈计数为 1456。轮径、左右轮方向以及需要平面坐标时的轮距，应在实现编码器里程时单独确定。

## 8. 本次验证

- Debug 和 Release 均编译、链接通过。
- Debug：Flash 63212 字节，RAM 8592 字节。
- Release：Flash 59524 字节，RAM 8576 字节。
- 主机算法回归：静止、初始倾斜、变 dt 转动、相对 Yaw、四元数归一化、倾角反馈、运动加速度门限、缺样恢复、非法输入。
- 主机交互回归：OLED 三角度/等待/GAP 页面，位置命令已移除，六列 POSE 帧，原有 MPU_C 帧保留。
- 回归程序放在临时目录，没有往项目重新加入 tests 或 tools。

本轮未烧录，也未进行板上姿态精度验证。前次板端验证时存在 I2C 超时，不能用本轮的软件检查结果宣称硬件通信已恢复。
