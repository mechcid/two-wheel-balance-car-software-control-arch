# UART 数值解析优化说明

日期：2026-10-12。

串口命令的数值转换已改为轻量十进制解析。修改位于 `module/base/src/uart_debug.c`，公开接口说明位于 `module/base/inc/uart_debug.h`。

## 为什么修改

原来的 `TYPE_FLOAT` 使用 `strtof()`，`TYPE_INT` 使用 `strtol()`。其中通用浮点文本转换引入了十六进制解析、多精度转换、区域设置及软件双精度运算等依赖，对当前普通十进制调参用途来说占用较大。

本次移除这两个转换调用以及不再需要的 `stdlib.h`、`errno.h`，以两个文件内部函数替代。命令注册接口、变量类型、回调、标志位和串口收发流程沿用原实现。

## 输入格式

完整命令仍是 `@命令:参数\r\n`，数值部分允许开头有一个 `+` 或 `-`。

| 参数类型 | 允许示例 | 拒绝示例 |
|---|---|---|
| TYPE_INT | `0`、`+123`、`-123`、`00123` | `1.0`、`1e3`、`0x10` |
| TYPE_FLOAT | `123`、`-12.75`、`+.5`、`5.`、`-0.0` | `1e3`、`nan`、`inf`、`0x1.2p3` |
| 两者共同要求 | 至少有一个数字，完整参数合法 | 空参数、单独正负号、空白、尾随字母 |

整数不允许小数点；浮点参数允许整数写法。浮点参数最多一个小数点。前导零不改变十进制含义。

例如 `@ml:-12.75\r\n` 仍然可以使用。`@ml:12abc\r\n` 会报错，不会只取出前面的 12。旧标准库解析能接受的一些格式（例如前导空白和科学计数法）现在明确拒绝。

原有接收器限制单条命令正文最多 63 字符，包含命令名和冒号，数值部分也受这个总长度限制。

## 整数解析

`parse_integer()` 先读取正负号，再用无符号数累加绝对值。每读一个数字，都先检查下一次“乘 10 再加数字”是否超出目标范围。

当前 STM32 的 int 是 32 位，支持完整范围 `-2147483648` 到 `2147483647`。负数的最小值有专门处理，避免直接对 INT_MIN 取负引发溢出。

整数转换不经过 float，因此 `16777217` 这类不能被单精度浮点数精确表示的整数也能正确接收。

## 小数解析与精度

`parse_decimal()` 使用单精度运算：

- 整数部分逐位执行 `value = value * 10.0f + digit`。
- 小数部分按 0.1、0.01、0.001 等位权累加。
- 最后应用正负号，保留负零。

小数部分单独累加，避免把长小数全部拼成一个大整数而导致不必要的中间溢出。转换不需要动态内存、double、指数解析或通用多精度库。

这是面向调参的近似转换，保留 float 原有表示精度，但不保证任意长数字和范围边界的舍入与 `strtof()` 完全相同。连续计算会有舍入误差，超出精度的小数尾数可能不再改变结果。极接近浮点上限、下限的输入不应作为它与标准库逐位相等的保证。

中间结果变成非有限值时返回失败；非零输入太小、最后完全变成零时也返回失败。姿态计算使用的 float 和数学函数继续保留。

## 错误输入的行为

解析只写局部临时变量；全部检查通过后才更新注册的变量。失败时输出错误消息，并在回调和标志位处理之前返回。因此失败命令不会修改目标值、执行回调或置位通知标志。

数值格式检查只确认数字能否转换。具体参数是否适合电机、PID 或其他模块，仍由对应业务代码检查。

## 实测体积

使用本机 GCC 13.2.1、项目现有编译配置，优化前后比较：

| 配置 | 修改前 Flash | 修改后 Flash | 减少 | 修改后占 64 KiB 比例 |
|---|---:|---:|---:|---:|
| Debug | 63212 B | 44932 B | 18280 B，约 17.85 KiB | 68.56% |
| Release | 59524 B | 41132 B | 18392 B，约 17.96 KiB | 62.76% |

RAM 链接占用也减少 376 B：Debug 从 8592 B 变为 8216 B，Release 从 8576 B 变为 8200 B。这个统计不代表测量过运行时栈峰值。

最终 ELF 中已不存在 `strtof`、`strtod`、`strtol`、十六进制浮点解析和原多精度转换相关符号，也没有原转换链路引入的软件双精度运算符号。原有整数格式化输出仍然存在。

## 验证范围

- Debug、Release 编译和链接通过。
- 主机编译真实 `uart_debug.c`，使用 HAL 模拟层验证串口接收、命令解析和回调。
- 覆盖 int 上下限、边界外值、正负号、前导零、小数点各种合法/非法位置、空白、指数、特殊数值、溢出和极小非零输入。
- 10000 组整数与预期整数比较；10000 组普通十进制小数与主机标准库比较，误差均通过 `max(1e-7, |参考值| × 2e-6)` 的测试门限。这是测试范围内的结果，不是对所有输入的误差保证。
- 检查错误输入不赋值、不触发回调和标志，检查实际 `@...\r\n` 字节拼帧流程。
- AddressSanitizer 和 UndefinedBehaviorSanitizer 检查通过；当前运行环境不支持 LeakSanitizer，因此关闭其泄漏检测。新解析器不分配动态内存。
