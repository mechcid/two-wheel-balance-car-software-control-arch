# 调度器与采集架构

> 2026-09-22 新增电机任务及运行时恢复限制，见 [电机控制接入说明](电机控制接入说明.md)。

## 1. 文件职责

| 文件 | 职责 |
|---|---|
| `module/src/scheduler.c`、`module/inc/scheduler.h` | 通用协作式调度；仅依赖标准 C 头文件，无 HAL、设备或动态内存依赖 |
| `module/src/mpu6050.c` | 原有底层初始化、原始读取与诊断；保留尾字节保护 |
| `module/src/sensor_app.c` | 保存原始/修正两份样本，单位转换和校准，提供只读数据与状态 |
| `module/src/display_app.c` | 将传入的修正数据转换成 OLED 页面，不决定周期 |
| `module/src/telemetry_app.c` | 应用命令、状态汇总、修正数据上报，不决定周期 |
| `module/src/oled.c`、`uart_debug.c` | 继续负责通用屏幕传输、串口收发和解析 |
| `Core/Src/main.c` 用户区 | 绑定 I2C2/USART2，初始化设备，任务包装函数与任务列表 |

```text
main ── Scheduler_Run(tasks, count, HAL_GetTick())
            ├─ SensorApp_Update(now)
            │    └─ MPU6050_Read → 私有 raw_sample → 校准 → corrected_sample
            ├─ DisplayApp_Render ← const SensorSample *
            ├─ TelemetryApp_Report ← const SensorSample *
            ├─ TelemetryApp_Poll：处理命令
            ├─ DisplayApp_Poll：发送一块显存
            └─ 到期检查设备是否需要恢复
```

这次没有改外设引脚、底层 UART/OLED 驱动或加入平衡控制。`sensor_app` 仍通过 HAL 类型绑定 STM32 I²C，尚不是跨 MCU 的纯平台无关驱动；独立调度器则可以直接移植。

## 2. 调度器如何复用

复制 `scheduler.h/.c`，把源码加入目标工程；不需要 STM32、HAL 或 RTOS。

```c
static void task(void *context)
{
    /* 完成一次有限工作，使用 context 获取所需数据。 */
    (void)context;
}

static SchedulerTask tasks[] = {
    {.function = task, .context = NULL, .period_ms = 20, .enabled = true},
};

/* 初始化一次；now_ms 由你的平台提供。 */
Scheduler_Init(tasks, 1, now_ms);
/* 在主循环中反复调用，每次传最新的毫秒时间。 */
Scheduler_Run(tasks, 1, now_ms);
```

成员：函数地址、用户参数、周期、上次调度时间、启用标志。任务列表及 context 指向的对象必须在使用期间一直有效。

### 执行规则

- `Run` 从前到后遍历一次后返回，没有内部死循环；每个任务每轮最多执行一次。
- 周期 0：每次主循环执行一次。非零周期允许范围 1…INT32_MAX ms，超出范围的表项不执行；设置函数返回 false。
- 初始化后等待一个周期才首次执行；周期 0 的任务在第一轮执行。
- 到期判断使用无符号差值 `now_ms - last_run_ms`，可跨 uint32_t 计数回绕；必须持续轮询，不能跨完整计数周期仍期待恢复遗漏次数。
- 延迟后只执行一次，不补历史次数；下次从这次的调度时间计算。它会随延迟漂移，不保证硬实时节拍。
- 一轮使用同一个时间快照。前一个任务耗时不会自动更新本轮 now；下一轮传入新时间。`last_run_ms` 记录该轮调度时间，不一定是回调实际开始的精确时刻。
- 空列表、空函数会被安全跳过。无动态分配，无任务抢占，无线程同步；同一执行上下文使用，不能从中断并发修改表，也不能递归调用 Run。
- `Scheduler_SetPeriod(&tasks[i], period, now)` 修改周期并重新计时。
- `Scheduler_SetEnabled(&tasks[i], enabled, now)` 在启停状态变化时重新计时；恢复后不补暂停期间的调用。

回调必须及时返回。阻塞 I²C、长计算、延时都会推迟其他任务；列表顺序仅是顺序，不是抢占优先级。

### 当前 main 中的周期

| 任务 | 周期 |
|---|---:|
| 采集并修正 | 10 ms |
| UART 命令处理 | 每轮 |
| 生成显示内容 | 200 ms |
| 串口上报 | 200 ms |
| OLED 分块发送 | 每轮 |
| MPU 故障恢复检查 | 1000 ms |
| OLED 故障恢复检查 | 2000 ms |

修改频率只需修改 main 的任务表。新任务通过 `void (*)(void *)` 包装函数适配，避免不兼容的函数指针强制转换。

当前 MPU 底层配置的硬件输出速率仍为 100 Hz。主循环读取周期与传感器内部采样率是两件事：读得更快可能重复同一数据，读得更慢会跳过中间样本；本次未增加 FIFO 或同步修改硬件采样率的接口。

## 3. sensor_app 的数据与接口

### 私有原始数据

`static MPU6050_Sample raw_sample`：保存六轴及温度的原始 int16_t 计数，不提供外部读取接口。硬件诊断可在调试器中查看 Debug 固件变量，正常业务不得绕过修正接口。

### 对外修正数据

`SensorSample`：

- `ax_g/ay_g/az_g`：g。
- `gx_dps/gy_dps/gz_dps`：度/秒。
- `temperature_c`：摄氏度。
- `timestamp_ms`：成功样本采集开始时由调用者提供的时间；不是传感器硬件时间戳。
- `valid`：是否至少成功发布过一份样本，不代表这份数据永不过期。

`SensorApp_GetSample()` 返回 `const SensorSample *`，调用者只读。当前全部任务串行运行，发布不需要锁；以后迁入 RTOS/中断并发环境，需要快照或同步保护，const 不能保证并发读取一致。

### 刷新过程

`SensorApp_Update(now_ms)` 不读系统时钟、不判断周期、不显示、不打印，也不自动重连：

1. 调用 MPU 驱动取得完整的新原始数据。
2. 单位转换与校准，计算新修正样本。
3. 保存原始样本并发布修正样本，增加成功计数。

失败时返回错误，记录故障并标记设备未就绪；上一次修正样本及其时间戳保持不变。未就绪时的空调用不增加总线读取失败计数。主程序定时调用 `SensorApp_Reconnect()` 恢复设备。

`SensorApp_Init(bus)` 清空样本和计数、恢复默认校准，并初始化设备；`Reconnect()` 保留样本、校准和统计。两者底层仍包含 MPU 复位/稳定等待，约 200 ms 延时外加总线时间，运行中恢复会拖慢其他任务。要做严格平衡控制时，应继续把恢复拆成非阻塞状态机。

main 将“设备就绪、样本有效且年龄小于 500 ms”作为当前可用条件，传给显示和上报函数；过期时显示等待信息并暂停样本上报。500 ms 是 main 中当前的显示/遥测策略，不是控制器安全阈值；更改采集周期时需要一并评估。

## 4. 校准入口

`SensorApp_SetCalibration()` 在下一次成功刷新时生效；传 NULL 恢复默认值。

```text
加速度 = (raw / 16384 - accel_bias_g) × accel_scale
角速度 = (raw / 131   - gyro_bias_dps) × gyro_scale
温度   = raw / 340 + 36.53 + temperature_offset_c
```

各轴独立配置。默认偏置 0、比例 1、温度补偿 0，只转换单位；没有捏造校准值，因此静止约 1.2g 的偏置仍会出现。

参数校验拒绝非有限数值、非正比例及过大的系数：加速度偏置绝对值 ≤16g、角速度偏置 ≤2000°/s、比例 ≤10、温度补偿绝对值 ≤200℃。这些是输入保护范围，不是推荐校准范围。

目前 `correct()` 是清晰的内部算法入口，没有加入未经选择的滤波或姿态算法。将来加入依赖 dt 的算法时，可用相邻样本时间差，不能暗藏固定采样周期。修改 MPU 量程时必须同步调整这里的灵敏度系数。

## 5. 串口协议变化

外部只使用修正数据，因此旧的原始计数 `MPU,...` 帧替换为：

```text
MPU_C,timestamp_ms,ax_mg,ay_mg,az_mg,temp_mC,gx_mdps,gy_mdps,gz_mdps
```

这些是修正物理值乘 1000 后截断的整数；1g=1000mg，1℃=1000m℃，1°/s=1000mdps。避免启用浮点 printf，同时用新标记明确区别旧协议。若上位机脚本按 `MPU,` 或原始计数换算，需要更新解析；蓝牙助手的文本接收无需更改。

保留 `@ping`、`@status`、`@stream:0`、`@stream:1`（CRLF 结束）。状态查询可访问设备元信息及计数，但不输出原始测量。移除了应用层 `@diag` 命令与启动自动诊断，底层 `MPU6050_Diagnose` 仍保留用于专门诊断。

状态查询有意汇总 OLED/UART/传感器，这是调试业务的职责；可复用的 sensor_app 不依赖这些输出模块。
