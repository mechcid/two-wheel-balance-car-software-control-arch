# 姿态解算架构与滤波笔记

本文整理 `module/pose_estimate` 中姿态解算部分的职责、接口与滤波原理。传感器测量含义、比力与重力、校准、样本时间戳和序列号，以及 `sensor_app` 的职责，统一参见 [MPU6050 模块架构笔记](MPU6050.md)，这里不再展开。

## 1. 模块分工

姿态解算由 `motion_app` 和 `motion_estimator` 配合完成：

| 模块 | 主要职责 | 依赖与边界 |
| --- | --- | --- |
| `motion_app` | 消费新样本、计算实际时间间隔、调用算法、处理缺样与记录统计 | 依赖采集接口与初始化时注入的时钟函数 |
| `motion_estimator` | 姿态运动学计算、传感器融合、滤波、输入检查与失效后的姿态重建 | 不依赖 HAL、硬件采集或系统时钟，不负责调度 |

当前调用关系为：

```text
主循环调用 SensorApp_Poll()，由传感器模块按周期执行内部更新
    → 调用 MotionApp_Poll()，消费有效的新样本并计算 dt
    → 调用 MotionEstimator_Update()
    → 更新整车状态并运行控制模块
```

整理架构时，可以先将 `motion_estimator` 当作算法库使用，重点掌握输入、输出、状态和失效条件。公式推导可以后续学习，但算法原理成熟并不等于具体实现天然正确，仍需通过测试验证。

## 2. `motion_app` 的数据、状态与更新边界

`motion_app` 持有私有的 `MotionEstimator` 实例。四元数和低通滤波状态只在内部使用，可通过调试器观察；对外发布已经计算好的欧拉角，不再暴露算法内部状态。

### 2.1 完整的姿态样本

`MotionSample` 通过 `SampleSource imu_source` 记录本次计算实际消费的 IMU 序号和时间戳。它与姿态一同成功发布，等待、输入失效或计算失败时保留上次来源。姿态自己的输出序号与 IMU 序号独立，不能直接比较；需要组合姿态与当前 IMU 时，应比较 `imu_source` 的两个字段。来源标识只在当前初始化生命周期内有效，不用于跨模块重置追溯。

`MotionSample` 将一次发布的数据与元信息放在一起：

| 成员 | 含义 |
| --- | --- |
| `data` | `EulerAnglesDeg`，包含 `roll`、`pitch`、`yaw`，单位为度 |
| `timestamp_us` | 本次姿态对应的输入测量时间，不是计算完成时间 |
| `sequence` | 姿态成功发布序号，与传感器输入序号独立 |
| `valid` | 当前姿态样本是否允许使用 |
| `discontinuity` | 是否曾发生无法补回的姿态中断；恢复有效后仍保留 |

算法成功后先转换欧拉角，再整体发布样本。只有成功发布才推进时间戳和序号。失败时保留上一次数值、时间戳和序号，清除 `valid`，不把旧姿态标记成新数据。

### 2.2 模块运行状态

`MotionAppStatus` 保存运行状态 `state`、成功次数 `succ_update_count`、失败次数 `fail_update_count`、最近输入间隔 `last_dt_s`，以及加速度参考是否可信 `accel_trusted`。

运行状态区分未初始化、等待首份输入、正常运行、输入不可用、输入超时和算法更新失败。正常运行时，短暂等待下一份样本不会改变运行状态。失败计数仅记录算法更新失败，不在等待或超时期间反复递增。

### 2.3 私有更新与公开轮询

- `MotionApp_Poll()`：主循环每轮调用；先检查输入有效性和超时，再检查新输入及最小处理间隔，两者都满足才触发更新。它不采集传感器，也不维护与传感器无关的固定相位。
- `static MotionApp_Update()`：处理一份输入，计算时间间隔、检查连续性、调用算法、发布样本并维护诊断状态。外部不能调用。

模块分别保存“最近消费的输入序号”和“输出发布序号”。算法失败后也记录输入已被消费，避免反复计算同一份数据。

头文件通过 `MOTION_UPDATE_HZ` 独立配置处理频率上限，`MOTION_MIN_UPDATE_INTERVAL_US` 表示两次算法尝试开始时刻的最小间隔。首份输入立即处理；只有实际尝试更新才记录处理时间，没有新输入或间隔未到都不推进时间、也不消费输入。积分 `dt` 仍取实际消费的输入时间戳之差，不使用配置周期代替。

默认上限为 400 Hz，给 200 Hz 输入的到达抖动留余量，实际姿态输出仍约为 200 Hz。严格设置相同的 200 Hz 上限时，启动阶段不规则间隔可能造成持续处理延迟。若降至 100 Hz，只消费最新输入，会跳过中间测量；时间戳差不能恢复跳过的运动变化。同时，当前 LQR 的最大允许间隔为 7.5 ms，不能仅修改姿态频率就认为控制仍可正常运行。输入失效以及已发布姿态的过期检查始终执行，不受处理频率限制。

### 2.4 对外查询接口

| 公开接口 | 外部获得的内容 |
| --- | --- |
| `MotionApp_GetSample()` | 内部 `MotionSample` 的只读指针 |
| `MotionApp_GetStatus()` | 内部 `MotionAppStatus` 的只读指针 |

调用者无需再从不同接口拼接角度、时间戳与有效标志。需要保留历史结果时，应复制样本；当前接口仍只约定主循环串行访问。使用结果时还需按场景判断新鲜度和连续性。

主循环保持“传感器轮询 → 姿态轮询 → 等待与当前测量匹配的新姿态样本，再更新整车状态和 LQR”的顺序，不引入独立控制相位。采集的 5 ms 周期仍由 `sensor_app` 管理，移除姿态模块不会停止传感器采集。

## 3. `motion_estimator` 的使用约定

算法接收三轴加速度计读数（g）、三轴角速度（°/s）和相邻样本的实际时间间隔 `dt`（秒）。调用者持有算法实例，并通过指针传入；算法维护历史姿态与滤波状态，因此不是无记忆的单次计算函数。

| 状态成员 | 含义 |
| --- | --- |
| `q[4]` | 姿态四元数，顺序为 w、x、y、z，将机体坐标转换到参考坐标 |
| `valid` | 当前姿态估计是否有效 |
| `accel_trusted` | 本轮是否接受加速度计作为倾角参考；为假不一定意味着整个姿态无效 |
| `discontinuity` | 曾因缺样等原因失去姿态连续性；恢复有效后仍保留，重新初始化才清除 |

首次启动应保持静止，以建立初始倾角。缺样后恢复时，算法重新建立倾角并保留上次航向，不补算缺失期间的旋转。

当前欧拉角采用以下旋转约定：

$$
R = R_z(\mathrm{yaw})R_y(\mathrm{pitch})R_x(\mathrm{roll})
$$

它可以描述为绕固定轴依次旋转的**外禀 XYZ**，也等价于绕随动轴依次旋转的**内禀 ZYX**。讨论内禀或外禀时必须同时说明旋转顺序。

## 4. 滤波原理与当前实现的关系

以下保留滤波原理笔记，用于理解融合思路，不将其视为当前代码的逐行说明。当前实现对加速度向量低通滤波，以重力方向偏差修正角速度，再更新并归一化四元数；它没有分别执行三个单轴高低通滤波器。

滤波选择的依据是有用信息与误差在频率上的分布。频率在这里指信号变化的快慢，不是处理器运行频率。滤波器不能仅凭频率判断一个变化是真实运动还是噪声。

## 5. 一阶低通滤波

低通保留缓慢变化，削弱快速变化。常用递推形式：

$$
y_k=\alpha y_{k-1}+(1-\alpha)x_k
$$

其中 $x_k$ 是本次输入，$y_k$ 是本次输出。代码示意：

```c
filtered = alpha * filtered + (1.0f - alpha) * input;
```

例如上一输出为 10，本次输入跳到 20，取 α=0.9，本次输出为 11。若输入持续为 20，输出逐渐接近 20；若只是短暂跳动，影响较小。

α 越接近 1，平滑越强，响应也越慢。初次使用通常令输出等于第一份有效输入，避免从零启动带来的额外过渡。

低通可用于抑制高频噪声，也可用于提取缓慢变化的参考。真实的快速动作同样会被削弱或延迟，因此平衡控制不能无限加强平滑。当前代码滤波的是加速度向量，而不是先算出倾角再滤波。

## 6. 一阶高通滤波

高通保留快速变化，削弱恒定值和缓慢变化。与上述低通配套的递推形式为：

$$
y_k=\alpha(y_{k-1}+x_k-x_{k-1})
$$

```c
filtered = alpha * (filtered + input - previous_input);
previous_input = input;
```

$x_k-x_{k-1}$ 提取输入变化。输入不再变化时，这一项为零，输出逐次乘以 α 并衰减到零。初始化通常设置 previous_input 为第一份有效输入、filtered 为零。

因此，高通不能独自保存长期不变的倾角：车身一直保持 10°，高通输出最终会接近零。缺失的缓慢部分需要由加速度计的低通参考补充。

## 7. 系数、采样间隔和截止频率

对本文的一阶离散实现，可以按时间常数设置系数：

$$
\alpha=\frac{\tau}{\tau+dt},\qquad
\tau=\frac{1}{2\pi f_c}
$$

- $dt$：本次与上次有效数据的时间间隔，单位秒。
- $\tau$：时间常数，单位秒。
- $f_c$：设计的截止频率，单位 Hz。

这对应一阶连续滤波器的后向欧拉离散形式。采样间隔足够小时，实际离散截止频率接近设计值；滤波器在截止频率附近逐渐衰减，不是一刀切。

例如 dt=0.01 秒、设计 fc=1 Hz，可得 τ≈0.159 秒、α≈0.941。该例仅说明计算方法，不是本项目的建议参数或实测整定结果。

改变采样周期时，应同步重新计算系数。若使用固定 α，却改变更新频率，实际滤波效果也会改变。若数据丢失或长时间中断，不能盲目继续积分，应设计异常时间间隔的处理策略。

当前代码使用 `gain = k / (1 + k)`，其中 `k = 2π × accel_cutoff_hz × dt`，再执行 `filtered += gain * (input - filtered)`。这里的 `gain` 等于上式中的 `1 - α`，会随实际 `dt` 变化。

## 8. 高低通如何组成互补滤波

针对单个倾角，可以把两条信息通道相加：

$$
\theta=\operatorname{高通}(\theta_{\text{陀螺仪积分}})
+\operatorname{低通}(\theta_{\text{加速度计}})
$$

匹配的一阶连续滤波器满足：

$$
H_{\text{高通}}(s)=\frac{\tau s}{1+\tau s},\qquad
H_{\text{低通}}(s)=\frac{1}{1+\tau s}
$$

$$
H_{\text{高通}}(s)+H_{\text{低通}}(s)=1
$$

这就是“互补”的数学依据。假设两路都能测量同一真实倾角，匹配的滤波器使真实信号的快慢部分合起来得到完整响应，同时利用两路误差特点的差异。公式中的 s 是拉普拉斯变换变量，用于描述滤波器响应，不是要直接代入代码的参数。

实际代码通常把两条通道合并成一个递推式，不单独保存一个不断增长的陀螺仪积分角度：

$$
\theta_k=\alpha(\theta_{k-1}+\omega_k\,dt)
+(1-\alpha)\theta_{\text{加速度计},k}
$$

```c
angle = alpha * (angle + corrected_rate * dt_s)
      + (1.0f - alpha) * accel_angle;
```

其中角速度已做零偏补偿；angle 与 accel_angle 单位一致，角速度单位乘秒后也要得到相同角度单位。该式用于解释单轴原理，不可直接把三个轴独立套用并宣称完成任意三维姿态解算。还需处理角度跨 ±180° 的差值等问题。

**高通针对的是陀螺仪积分得到的角度，不是直接对原始角速度做高通。** 持续匀速转动时，角速度是恒定的有效输入；高通会逐渐把它消掉。原始角速度有高频噪声时，反而可以适度低通。

## 9. 与卡尔曼滤波的关系及边界

简单互补滤波由设计者设置融合权重。卡尔曼滤波则建立状态与观测模型，先预测，再根据预测不确定性和测量噪声估计计算修正增益。倾角模型还可以把陀螺仪零偏作为待估计状态。

卡尔曼滤波并非天然比互补滤波准确，效果取决于模型、参数与运动条件。两者都不一定是姿态计算之前的独立平滑步骤，而可以直接承担姿态融合。

当前项目没有使用卡尔曼滤波。这部分作为算法比较笔记保留，不代表已经实现了相应状态估计。

结合前文所引用的加速度测量限制，当前算法使用模长与方向残差共同判断加速度是否可信；仅靠滤波不能消除观测本身的歧义。即使三轴合成值接近 1 g，也不能单独证明没有运动加速度。
